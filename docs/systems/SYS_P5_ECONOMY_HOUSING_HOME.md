# SYS P5 — Economy Ledger, Rental Housing and Home Objects

Issue [#29](https://github.com/MohamedXIV/nile-kiosk/issues/29). Production modules: `economy_world.gd`, `housing_world.gd` under `scripts/core/`. The WorldKernel is **the only mutation boundary**: core snapshot schema **v6** includes full `economy` and `housing` state and always rebuilds them from audited events. D001 `tea_steps` and V001 furnishings remain **spikes**, not the source of gameplay truth.

## Currency and audit: no arbitrary balance or loan mechanics

- `economy.fund {transaction_id, amount_minor, source_id}` (trusted `system:treasury`) creates a **paired transfer** from `world:treasury` to `player` with explicit source provenance. **No default starting money is invented.** This is a source injection contract for authored starting grants/earnings rather than an economy balance choice.
- `economy.pay {transaction_id, recipient_id, amount_minor, cause_id}` (player) spends on allowed world expense accounts (vendors, landlord), rejects insufficient funds and invalid amounts.
- `economy.refund {transaction_id, original_transaction_id}` (trusted `system:treasury`) reverses a previous standalone `economy.pay` player-debit transfer exactly once, never twice. **Housing rent and furniture purchases cannot be refunded in isolation**, because that would leave the entitlement or furniture behind. They require a future domain-specific atomic compensation/reversal policy; the command explicitly returns `DOMAIN_REFUND_REQUIRED`.
- Each accepted transfer writes **two equal/opposite journal entries** in integer minor units (explicitly EGP piastres when the authored content uses Egyptian currency), with transaction ID, world event ID, minute, owning command kind and cause. Accounts include `player`, `world:treasury`, `world:vendors`, `world:landlord`, `world:customers`. External world accounts may go negative to model exogenous receipts; **the player cannot**. Signed balances, journal amounts and cumulative totals are bounded to JSON-safe integer ranges. Every ID is once-only, even if retried under a new command ID; exact command replays are handled by the P0 receipt. No debt interest, income tax, exchange rate or credit balance is invented.
- `economy.recipe.price.set {recipe_id, amount_minor}` (trusted `system:pricing`) provides authored recipe prices, allowing later changes **without retroactively changing a frozen order quote**.
- P4 `order.deliver` still consumes an actual prepared P3 item in one atomic event and leaves an *unpriced pending* payment claim. `economy.order.quote {claim_id}` freezes a catalog amount against the existing claim. `economy.order.settle {claim_id,transaction_id}` (trusted `system:service`) atomically books a world-customers → player ledger transfer **and** marks the P4 order/claim settled. Duplicate claims or transactions cannot increase money twice. An unquoted claim is never settled; a future pricing adapter is responsible for when to quote/settle, rather than pretending a delivered order was already paid.

**Security boundary:** `actor_id` is provenance and policy at the trusted WorldKernel interface, **not cryptographic authentication**. Scene/controller/API bridges must provide authenticated origin and never allow untrusted clients to forge `system:` identities. No network/multiplayer authorization is promised.

## Housing: authored rights and reversible arrears rule

- `housing.unit.register {unit_id,location_id,kind,area_sqm,rent_minor,period_minutes}` creates authored units (`roof` or `apartment`). The **starter roof room** has no rent obligations and can be granted via explicit `housing.roof.grant {unit_id}` (trusted `system:bootstrap`); no one automatically owns/leases a 60m² flat. A **south 60m² apartment** can be defined as content (`kind: apartment, area_sqm:60`) but its actual rent and period must be provided; the issue's 200/1000 EGP numbers are **not** system constants. Duplex purchase/construction stays uncommitted.
- `housing.lease.start {lease_id,unit_id,transaction_id}` requires a registered vacant apartment, no unpaid previous lease for that unit, player affordability and a unique lease/transaction ID. It debits one authored rent period and creates one recurring P1 `housing.rent.due` job, atomically with the entitlement. Rent period is **simulation minutes from authored data**, no implicit one-month duration.
- When an installment becomes due, the scheduler records a due event and increases the lease's `dues_owed`; **no automatic overdraft**. Under the explicitly reversible policy adopted for P5, an active unit's gameplay access is **suspended** while installments are outstanding, but the lease is **not automatically evicted**. `housing.rent.pay {lease_id,transaction_id}` pays exactly one missed installment, once. When all arrears are settled, access resumes. One large world advance and multiple smaller ones assess the same dues.
- `housing.lease.end {lease_id}` deactivates access and cancels future due events. **Historic arrears survive termination** and must be cleared before another lease of that unit. Ending a lease does not refund consumed rent or delete furniture.
- `WorldKernel.can_access_unit(unit_id)` is a canonical **rights projection**, separate from scene rendering/teleporting/locks. The P2 player location must match the unit location for player home actions; presentation/navigation adapters must enforce actual transitions.

## Object ownership, placement, interactions

- `home.type.define {type_id,price_minor,actions}` registers authored furniture type and valid interactions. No hardcoded bed/chair catalog or price.
- `home.object.grant {object_id,type_id}` (trusted bootstrap) records an explicit free starter acquisition. `home.object.acquire {object_id,type_id,transaction_id}` is a player purchase charged atomically from the same ledger when the authored price is nonzero.
- `home.object.place {object_id,unit_id,slot_id}`, `home.object.store {object_id}`, `home.object.interact {object_id,action_id}` validate ownership, unit access, player presence, stored/placed lifecycle and a single object per logical slot. Both placement and interaction persist along with a use counter and last action event ID.
- **Logical slot IDs are not pixel coordinates.** A future V001 scene adapter should map authored slots to positions and enforce visual collision/layout. Storing or moving items cannot bypass locked rooms; rent arrears never silently destroy owned belongings. No furniture effects (sleep recovery/comfort/mood) are fabricated yet: only the world-verified action and provenance are canonical.

## Replay, integration and deferrals

Version **6** adds `economy` and `housing` as independent domain sections in the WorldState envelope; versions 1–5 are explicitly rejected until a real migration path exists. `restore_snapshot` rebuilds all P0–P5 events, checks planned ledger transfers and scheduled housing dues, verifies every derived field and rejects tampering without modifying the current world. Orders, food, NPC presence, rent and furniture remain source-owned systems inside the same event reducer.

`tests/test_sys_p5.gd` checks zero-sum accounting, affordability, refunds and double-ID behavior; real P2/P3/P4 order creation/delivery then price freeze and exactly-once settlement; starter roof entitlement and 60m² apartment separation; lease first-rent, overdue periods, frozen/reinstated access and termination; furniture purchase/placement/interaction and denial while remote; large-vs-small advances; disk save mid-lease and restored interactions; forged ledger/housing/command-event rejection. Tests run in the existing Godot 4.6.3 CI job alongside P0–P4/D001/V001 and unchanged Chromium narrative/Web acceptance.

Deferred: concrete rent/recipe/asset prices, loan/debt interest, work income balancing, property purchases, future duplex, physical building geometry, real door locks, furniture game effects, and network authentication. No property tycoon mechanics are implied by the ledger.
