# SYS P6 — Production Ink Narrative Bridge and Social Sessions

[Issue #30](https://github.com/MohamedXIV/nile-kiosk/issues/30). Production files: `scripts/core/narrative_world.gd` (versioned WorldKernel domain), `scripts/core/ink_world_bridge.gd` (actual inkgd runtime boundary), plus `world_state.gd` and `world_kernel.gd`. **D001 spike session orchestrators and the Dialogue Manager fallback remain unchanged**, and are not authoritative. Real Ink is the selected authoring runtime, not a world database.

## Ownership and contract

**WorldState v7** adds `narrative = {stories, sessions}` to the canonical event log, snapshots, reproducible replay, and strict old-version rejection. Each session carries identity, registered authored story ID, co-present initial participants, location, phase (`running | choice | finished`), pending choice point, Ink's actual native serialized cursor (chunked into bounded JSON-safe strings), visible line provenance/first-heard audience, and selected-choice event history. Sessions **do not** own the global clock, social/knowledge truth or separate copies of NPC/player location.

**InkPlayer is the text cursor and choice renderer only.** `InkWorldBridge` instantiates a distinct true `inkgd InkPlayer` for each session from its compiled Ink JSON, uses the `beat:<beat_id>` and `point:<choice_point_id>` author tags to bind spoken lines to explicit manifests, and routes `start/line/wait/select/finish` through validated `WorldKernel.dispatch` commands. A rejected line or choice restores the pre-step native Ink cursor, preventing an author-side advance without corresponding canonical truth. On load, it constructs fresh InkPlayers and restores **their real Ink states** from the kernel snapshot; this includes a pending choice, not merely a UI button or phase string. The bridge can attach any content story rather than special-casing tea, football or a two-story list.

`narrative.story.register {story_id, beats, choice_points}` records a bounded immutable authored manifest. Each beat binds one speaker and optional P2 fact ID. Choice points are authored, with stable option IDs and unique displayed text; each option declares `requires_known` (world-verified player facts), optional directional `requires_trusted` NPC, and optional authorized fact disclosure speaker/fact. Invalid IDs, duplicate story registration, undefined beats, malformed options or made-up choice IDs are rejected. Content assets are referred to by a trusted adapter-provided Ink file path; the domain itself never dynamically executes script text.

`narrative.session.start {session_id, story_id, participants, ink_state}` requires existing registered participants in one location (but **does not require the player to be one of them**). Two or more NPC/NPC sessions may run with independent cursors while the player moves, cooks, or makes a choice elsewhere. A session does not pause the P1 clock.

`narrative.line.commit {session_id, beat_id, mode, audience_ids, ink_state}` validates authored speaker and physical presence **at the event's world minute**. Public factual disclosures reuse **P2 social.speak planning and application in the SAME canonical narrative event**; all real co-present NPCs and player hear broadcasts, absent players hear nothing, and the first-heard provenance records the precise speaker, minute and event ID. P2 trusted disclosures require an explicit physically present trusted audience; broadcasting is rejected. Nonfact dialogue is still logged as authored beat/actual co-located witness set but creates **no canonical knowledge**. World facts are never inferred from a line merely existing in the Ink story, its on-screen transcript, an unaudited tag or a later player's movement.

`narrative.choice.wait {session_id, point_id, ink_state}` records a pending authored branch. `narrative_choices(session_id)` returns only options currently allowed by the player's P2 first-heard knowledge, listener-specific trust, and physical co-location; choices remain **revalidated when selected**, so stale UI options cannot bypass world truth. `narrative.choice.select {session_id, point_id, option_id, ink_state}` verifies the authored option and applies any explicitly authored P2 speaker disclosure in the same world event. `narrative.session.finish` commits final Ink cursor and terminal phase. Every command uses P0 idempotent receipts and cannot silently grant social familiarity or economic funds.

All narrative session commands require the trusted `system:narrative` adapter actor. **Actor IDs are a trusted local controller contract, not cryptographic authentication**; any future multiplayer/remote API must authenticate those origins separately.

## Tests, invariants and explicit deferrals

`tests/test_sys_p6_domain.gd` covers public NPC hearing while the player is absent, privacy denial without world mutation, directional trust and player-knowledge-gated choices, exact-once choice effects, tamper rejection and whole-world disk replay. `tests/test_sys_p6_ink.gd` uses **two independently instantiated actual InkPlayers** with new fixture Ink stories (not production-constraining content), mid-choice blocking, concurrent NPC/NPC talk, player offscreen rumor with no retroactive knowledge, actual Ink branching/reconvergence, native cursor save/disk reload, resumed selection with world minute provenance, second ungated fallback path, and v6 rejection. These tests share the existing pinned Ink compiler, Godot 4.6.3 native regressions and Chromium narrative smoke; no expensive new CI jobs.

The authored manifest is intentionally explicit and reversible, not a bespoke scripting language: authored Ink decides the prose and weave, bounded manifest tags map **which world facts an utterance could transmit**, P2 rules decide who really heard it. No world effects come directly from arbitrary Ink variables.

**Deliberate P7 boundary:** The production runtime's scene-level user interface/browser autosave integration and whole-world save migration belong to the later [SYS P7 #31](https://github.com/MohamedXIV/nile-kiosk/issues/31); existing D001 real-browser refresh tests remain regression coverage, **not evidence that this P6 production bridge already has a shipping Web UI**. Performance with large populations, authored plot scale, Arabic RTL, localization, high-fidelity distance/line-of-sight, relationship/mood automation and explicit public/private acoustic models remain unbalanced/unimplemented. NPC dialogue content counts are test fixtures, not a system completion criterion.
