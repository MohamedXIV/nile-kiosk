# SYS P7 — Whole-world Persistence & Integrated Godot/Web Runtime

[Issue #31](https://github.com/MohamedXIV/nile-kiosk/issues/31), parent [#23](https://github.com/MohamedXIV/nile-kiosk/issues/23). WorldKernel v7 remains the sole authoritative mutable world state for P0–P6 (world time, NPC schedules and hearing, cooking and stock, orders/service, prices/ledger and rentals, furnishings, canonical narrative sessions and real Ink cursors). **No new money/clock/ownership state resides in the scene.**

## Runtime integration

- `scripts/integration/world_session.gd`: user-facing facade over WorldKernel. All mutations use `command(command_id, actor_id, kind, payload)`, `advance`, or the adapter's world-verified Ink dispatch. `projection()` and `diagnostics()` are *copies*, including revision, receipt count, pending scheduler jobs, session count, world minute and cash. The controller tracks only transient UI diagnostics and path; scene navigation and visuals can change without changing economic rules.
- `load_existing()` distinguishes **NEW_WORLD** from **RESTORED**, and treats a corrupt/unsupported saved file as **INVALID_WORLD_SAVE**, without creating a fresh world and losing user data. It loads into a **new candidate WorldKernel** and swaps only if the whole event log and derived P0–P6 state passes strict v7 replay. Versions 1–6 are deliberately rejected, with an explicit migration boundary rather than made-up compatibility.
- `save()` invokes the original P0 durable temp-file/rename save, then independently reads the actual disk bytes into a new WorldKernel and compares against the current snapshot before reporting success. On Web, this uses Godot's real `user://` storage/IndexedDB rather than localStorage or an invented JS mirror. Save is read-only with respect to the simulation and creates no game events or duplicate receipts.
- Each named native InkPlayer is created from the real compiled story resource, and after loading the world it restores the saved native Ink cursor, even when the player is stopped at a choice. Dialogue adaptation is still **P6**: speaker/facts/choices are validated against P2 presence and trust on each event, not against old scene callbacks.
- `scenes/p7_world_integration.tscn` is an **interactive Godot + Web integration/debug scene** with code-drawn diagnostic presentation and keyboard actions for save, real Ink choice, finishing a preparation and paid order, paying rent and advancing NPC schedules. It is explicitly **not final art, presentation UX, or a hardcoded playable launch scene**. The existing D001 main scene and V001 art PR #20 remain unchanged.
- `scripts/integration/p7_acceptance_fixture.gd` supplies *test-only authored content*. Four NPCs plus a scheduled visitor, co-present/offscreen story sessions, a mid-cook live job, accepted NPC order, pending ledger price, a roof right and a separately leased 60m² apartment with a missed installment, and acquired/placed furniture. Example price/rent/funding amounts live **only in the integration fixture**, not in gameplay logic. The P7 scene reports world projections with JSON digest and event/receipt counts, not separate mock state.

## Native and real browser acceptance

The existing pinned Godot workflow adds `tests/test_sys_p7.gd`: a true production WorldSession with **two actual inkgd InkPlayers**, one mid-choice and one completed, saved at world minute 12 while a cooking job and order remain active and a scheduled visitor is present, with rent due, home objects placed and NPC-only gossip. Disk readback, destruction/reconstruction and replay must preserve the entire world and both cursors. Continue Ink branch/rejoin, complete food delivery and P4 claim settlement, pay overdue rent, advance offscreen NPC departure, save/reopen again, check zero duplicate payments/receipts, retry save, reject corrupt JSON, forged wallet/Ink state and older v6 without modifying the live world.

The **existing Chromium workflow**, in the same job as D001 DM/Ink + refresh regressions, exports the actual P7 production debug scene and runs `tools/web-production-world-smoke.mjs`. This browser test opens the compiled Godot Web game; verifies the initial full-world snapshot, saves, performs **real browser reload**, checks same digest/clock/receipts and pending Ink choice; finishes the Ink branch, cooking/service/payment and rent, advances the NPC schedule; saves, refreshes again and verifies the exact same state and no new transactions. It then saves a third time to establish that repeated saves are nonmutating. Both the scene and browser assert first-heard NPC gossip did **not** grant absent-player knowledge.

**Do not conflate P7 with the old D001 browser test.** P7's Chrome marker is `SYS_P7_CHROMIUM_PASS`, emitted only by the new full production scene test. Existing D001 evidence remains an independent nonregression check.

## Explicit residual boundaries

Content importer, long-lived save migrations (v1–v6), player-facing UI and V001 render/cutaway scene wiring, localization/RTL, app packaging and tab/profile cross-origin storage guarantees, service/NPC AI decision policy, autosave cadence and offline conflict resolution are future design/integration decisions. Nothing silently migrates unsupported saves or assumes a particular rental amount, NPC population or economic balance.
