## Authority and persistence

- `scripts/core/spatial_world.gd` adds `spatial = {graph, player:{room_id,x,y}}` to the full canonical **schema v8** event-sourced world snapshot. The authored graph is registered exactly once by `spatial.initialize {graph}` as a trusted `system:director` command, after C0 world bootstrapping. The graph is validated with the same packaged navigation schema as C1; the kernel verifies every portal's housing `unit_id` and target location against P5 and validates anchored NPC identities against P2. The graph payload is copied into the event so that future content-file edits cannot rewrite old runs.
- `spatial.player.move {dx,dy}` accepts signed integer steps of at most 18 units (Euclidean norm); rejects zero motion, wall crossing, invented actors and uninitialized worlds. It computes the next room pose itself and commits the result with stable event and receipt provenance. **Time is unchanged** by input movement; how real-time movement consumes world minutes remains a separate design question.
- `spatial.player.travel {portal_id}` checks door identity, correct current room, arrival/entry points and **actual proximity in the same canonical XY**, then requires P5 ownership/lease access for any residential gated destination. One event changes both the authoritative P2 `society.player_location` and spatial pose: no split world/scene transition. Once a graph is initialized, direct `social.player.place` commands are rejected (`SPATIAL_TRAVEL_REQUIRED`) to prevent remote teleports.
- `WorldSession.configure_navigation(path)` loads only trusted packaged `res://content/navigation/*.json` and commits the graph through the Kernel. An already-registered graph stays embedded and is never silently replaced by an updated file. The QA scene derives both drawn graph and player pixel state **only from `spatial_view()`**; render coordinates are mirrors, not authoritative state.
- **Replay-verified backward compatibility:** `WorldKernel.restore_snapshot` accepts an authentic v7 snapshot only after fully replaying **all original 17 fields/receipts/events** and comparing the complete v7 projection against that replay. It promotes a verified v7 snapshot into memory as v8 with **uninitialized spatial pose**, reports `MIGRATED`, and appends a distinct authored graph initialization event when the player enters a C2-enabled scene. v1–v6 still reject. Invalid/forged v7, missing data or corrupt files are rejected without changing the running world. Saving writes the validated v8 snapshot; future loads are ordinary `RESTORED`.
- P0–P7/C0 unaffected except the schema version and the new, explicitly constrained spatial commands. All game money, cooking, NPC routines, housing and independent Ink narrative remain world-owned and save with the same replay.

## Limitations

This is **bounded integer presentation-space movement**, not final pathfinding, continuous physics/colliders, collision with visible furniture, procedural NPC navigation, art projection/cutaway alignment, realtime speed balance or released content. The current C1 room geometry and cash/lease values are explicitly **QA content only**. The existing [V001 visual PR #20](https://github.com/MohamedXIV/nile-kiosk/pull/20) remains untouched; visual asset composition and topology must be approved independently.
